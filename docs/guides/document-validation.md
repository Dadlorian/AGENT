## What a caller uses

| Operation | Input | Output | Origin |
|---|---|---|---|
| validate | an instance document, the schema resource it is validated against, and the dialect that schema declares | an outcome carrying valid true or false and, when false, every violation located inside the instance, produced in one pass | sourced |
| check_schema | a schema resource and the dialect it declares | whether the schema is itself a valid schema of that dialect, judged against the dialect's meta-schema | sourced |
| prepare (proposed operation) | a schema resource plus the schema store its references resolve against | a reusable prepared-validator handle, so the cost of reading the schema is paid once and reused across instances (proposed) | proposed |
| dialect_in_effect (proposed operation) | a prepared-validator handle | the dialect URI the adapter actually resolved at run time, which is not necessarily the one the schema file declares (proposed) | proposed |

From `cap-document-validation` contract.operations; a row marked proposed is this repo's design, not a sourced fact.

## Adapters

| Role | Entity | Exposes | Cannot |
|---|---|---|---|
| today | E-adapter-in-place | validate and check_schema, served in-process in the same managed runtime as the caller | Proposed: cannot be reached from a runtime that cannot load it, and pays schema-reading cost on the interpreted path rather than generating code ahead of the first instance, so its per-instance cost is a function of schema size |
| second | E-swap-candidate-any-2020-12-validator | the same two operations, served by a validator that compiles the schema ahead of use in a different, natively compiled language runtime; the row names the candidate class rather than a product | Proposed: cannot share the caller's process objects or exception types, and cannot be handed a schema outside the declared dialect - which is the point, since anything it cannot implement was adapter detail leaking into the contract |

From `cap-document-validation-implement` adapters. Product names live only here and in the harness adapter files.
