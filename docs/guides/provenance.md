## What a caller uses

| Operation | Input | Output | Origin |
|---|---|---|---|
| attest (operation set the recorded standards fix a document format for, not a set of calls) | one or more subject digests, a predicate type, the predicate body, and the actor on whose behalf the statement is made | a signed envelope carrying an in-toto Statement over those subjects, returned to the caller and handed to the store | sourced |
| verify | an envelope and a trust policy naming the accepted signers and expected values | accepted or rejected with the reason; the platform's own implementation of this call is a convenience, and the contract is that an outside verifier reaches the same answer from the envelope alone | sourced |
| resolve (proposed) | a subject digest | every envelope whose statement names that digest as a subject, so a reader holding only an output can find what vouches for it | proposed |
| publish (proposed) | an envelope and the store it belongs in | a location a third party can fetch the envelope from without holding our credentials; where that location is an append-only log, the fetch also carries an inclusion proof | proposed |

From `cap-provenance` contract.operations; a row marked proposed is this repo's design, not a sourced fact.

## Adapters

|---|---|---|---|
| today | E-adapter-jsonl-evidence-records | The recorded adapter is JSONL evidence records: append-only local records naming what was run and the tree under test, integrity carried by a hash chain that our own reader recomputes | Cannot produce a signature at all, so it cannot serve verify for anyone outside this repository: the check is a rehash performed by code we wrote, against a file only we hold |
