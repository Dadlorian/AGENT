# progress — plan, develop, test, release, production as gated stages

One change goes to production. Five stages gate it, a bounded loop drafts it, a
fan-out tests it, a person releases it, and the effect that ships it declares
before it fires how it would be taken back. The run spans a crash and continues
under the ceiling it had left. `bash examples/progress/test.sh` is the visible
check.

Every row below is cited to a knowledge-base id, a research id, or a file with a
verbatim quote, or it says **proposed** and gives its reasoning. File evidence is
cited as `REF-<path>#<anchor>`, so one grep over this directory finds every id a
row carries and `provenance.json`'s `cites` list can be checked against it in
both directions (`test.sh` section 13). Every quoted string here is pasted out of
the record it names and grepped back into it verbatim by the same section: a
byte difference is a failure, not a note. Nothing here names a product.

## 3. The call

Four entries cover nearly every situation and all four enter through one shape
(`T-t6-02` "Four entries cover nearly every situation: a human, an event, a
schedule (time), and an external system or agent."). Each document validates
against `REF-examples/end-to-end/schemas/entry.schema.json` with that example's
own validator; the declaration inside `payload.progress` validates against
`schemas/progress.schema.json` with the *same* validator. No client library from
this repository is involved (`F-b1-05` "A caller needs no client library we
wrote.").

| Door | The one line a caller writes | The document behind it | What is different | What is identical |
|---|---|---|---|---|
| human (a shell or an IDE) | `python3 examples/progress/run.py --entry examples/progress/entries/human.json` | `entries/human.json` — `user:corey`, one direct hop | approves at the gate; the release ships and verification passes, so the run reaches promotion | one unit declaration, one envelope shape, one plan, one durable executor, one ceiling |
| event | `python3 examples/progress/run.py --entry examples/progress/entries/event.json` | `entries/event.json` — `service:checkout-ci`, two hops | the reviewer **edits**: the release note that ships is the reviewer's, so the effect's body differs from the human door's while every stage outcome up to the gate is the same | the same unit declaration, envelope shape, plan and ceiling |
| schedule | `python3 examples/progress/run.py --entry examples/progress/entries/schedule.json` | `entries/schedule.json` — `schedule:release-coupon-fix`, acting on a user's behalf, and the recurrence, zone, catch-up policy and nominal occurrence the fire came from | nobody is at a screen: the gate reaches its deadline, the unit ends `failed` at `release`, and no effect is ever declared. The envelope's key is the one the nominal occurrence derives | the same unit declaration, envelope shape, plan and ceiling |
| external (another agent) | `python3 examples/progress/run.py --entry examples/progress/entries/external.json` | `entries/external.json` — `agent:partner-release-bot`, three hops, `parent_correlation_id` and `depth: 1` | approves, the release ships, and post-release verification **fails**: the register is walked backwards and the effect is compensated | the same unit declaration, envelope shape, plan and ceiling |
| the unit behind all four | `intent.workflow_ref` → `pipelines/release-coupon-fix.json` | the task specification: five stages, their operators, the gate each one enters on, the loop's bound and per-iteration ceiling, the fan-out's shards, the evaluation's case set and baseline, the gate's offered decisions and deadline, and the effect's irreversibility class and its undo | nothing | one declaration, four doors |

Measured, not asserted: the four doors carry four actors, four run ids and four
correlation ids through one unit declaration, and the stage sequence is the
declaration's order at every door (`test.sh` section 1). The walk dispatches on
the stage's declared `op`, never on its id, so a sixth stage row added to the
document is priced into the plan's floor and worst case, walked in declared
order, committed and charged, with nothing in `run.py` naming it; a stage
declaring an operator neither the composition capability's schema admits nor
this area adds is refused `document-invalid` 422 before an executor is bound
(`test.sh` section 3, two differentials). The door the work came
in by is carried on every record and read by nothing in the pipeline document —
the same section's last check greps the declaration for the word.
