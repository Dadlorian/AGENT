# watch — how I see it from where I am, and the steps inside a unit

The unit runs somewhere the caller is not. This example is what the caller sees
while it does: a typed event stream, a task status, four kinds of telemetry
signal, and a receipt — rendered on the surface the caller declared, and
reassembled by grouping on the run id rather than by walking a trace parent.
`bash examples/watch/test.sh` is the visible check.

Every row below is cited to a knowledge-base id, a research id, or a file with a
verbatim quote, or it says **proposed** and gives its reasoning. File evidence is
cited as `REF-<path>#<anchor>`, so one grep over this directory finds every id a
row carries and `provenance.json`'s `cites` list can be checked against it in
both directions (`test.sh` step 11). Nothing here names a product outside the
adapters table.

## 3. The call

Four entries cover nearly every situation and all four enter through the same
shape (`T-t6-02` "Four entries cover nearly every situation: a human, an event, a
schedule (time), and an external system or agent."). Each document validates
against `REF-examples/end-to-end/schemas/entry.schema.json` with that example's
own validator; the watch declaration inside `payload.watch` validates against
`schemas/watch.schema.json` with the *same* validator. No client library from
this repository is involved (`F-b1-05` "A caller needs no client library we
wrote.").

| Door | The one line a caller writes | The document behind it | What is different | What is identical |
|---|---|---|---|---|
| human (a shell or an IDE) | `python3 examples/watch/run.py --entry examples/watch/entries/human.json` | `entries/human.json` — `user:corey`, one-hop chain | watches a `stream` from position 0 at `steps` detail, redacting nothing beyond the unit's own set | one unit declaration, one envelope shape, one emission path, one event vocabulary |
| event | `python3 examples/watch/run.py --entry examples/watch/entries/event.json` | `entries/event.json` — `service:alerting`, two-hop chain via token exchange | nobody is watching: a `poll` surface at `unit` detail, one operation for the whole unit, and the alert text redacted | the same unit declaration, envelope shape, emission path and event vocabulary |
| schedule | `python3 examples/watch/run.py --entry examples/watch/entries/schedule.json` | `entries/schedule.json` — `schedule:nightly-fault-sweep`, acting on a user's behalf | `sampling.head_percent: 50`, so some steps are sampled away while every metric, log record and problem object is kept | the same unit declaration, envelope shape, emission path and event vocabulary |
| external (another agent) | `python3 examples/watch/run.py --entry examples/watch/entries/external.json` | `entries/external.json` — `agent:partner-sre-bot`, three-hop chain, `parent_correlation_id`, `depth: 1` | subscribes from position 2 and declares `pause_for_decision`, so the run parks on a person and resumes as a second dispatch | the same unit declaration, envelope shape, emission path and event vocabulary |
| the unit behind all four | `intent.workflow_ref` → `units/observe-checkout-fault.json` | the task specification: isolation declaration, attempt class, three ceilings, the tool surface, and the observation declaration the platform will not let a caller narrow | nothing | one declaration, four doors |

Measured, not asserted: the four entry documents name one `workflow_ref` and the
unit name is read back off all four ledgers and matched against that file, the
four doors carry four actors, four run ids and four correlation ids, every signal
of every kind is stamped with the run id and the correlation id, and each run
returns exactly one group (`test.sh` step 1).
Correlation rides on those explicit attributes and never on trace parentage
(`F-a7-02` "Correlation must ride on an explicit resource attribute set at
dispatch.").

### What `payload.watch` declares, and where each field is read

| Field | Read at | What changes when it changes | Proved by |
|---|---|---|---|
| `surface` | `main()`, choosing the human-interaction adapter | `stream` renders 8 of 8 events and `poll` renders 0 of the same 8 — one store, two projections, and the store is byte-identical either way | `test.sh` step 6, differential |
| `since` | `render()`, at the `watch()` call | since 0 renders 11 events, since 2 renders 9, both ending at the same event; on a surface declaring `replayable_from_position: false` the same field returns a typed refusal instead | `test.sh` step 6, two differentials |
| `detail` | `Observation.close()` and `Observation.trace_for()` | `steps` emits 4 named operations and 4 minted traces; `unit` emits 1 of each and folds the step attributes onto it | `test.sh` step 3, differential |
| `redact_additional` | `Observation._redacted()`, on every attribute of every kind | with `task_summary` the value on the wire is `[redacted]`; without it, it is the caller's text — and `prompt` and `completion` are `[redacted]` in both | `test.sh` step 5, differential |
| `sampling.head_percent` | `Observation._kept()`, per span | 100 exports 4 spans, 0 exports none, and the cost total on the metrics is identical in both | `test.sh` step 4, differential |
| `pause_for_decision` | `run_unit()`, before the run finishes | on the same envelope, true parks at `input-required`, covers 2 correlation levels, puts `human.ask` and `human.decided` on the stream and returns a decision row; false covers 1, renders three fewer events and returns none | `test.sh` step 2, two differentials (`--pause` on the human door, `--no-pause` on the external one) |
| `sampling.retain_errors` — **absent by design** | the schema, at admission | a caller that adds it is refused 422; the retention of failures is not a member a caller has | `test.sh` step 4 |

And the fields outside `payload.watch` that this example is equally obliged to
read — two on the envelope's own intent and the observation declaration, three
leaves of the unit that were carried and are now read at a point of decision, and
the two ceilings that used to show only when they were crossed. The test each
row has to pass is the same one: give the field a second **legal** value and run
again, and the ledger and the report have to come back different. A field that
only moves the records at the value that breaks the run is proved at its
threshold and unproved everywhere a caller would actually set it.

| Field | Read at | What changes when it changes | Proved by |
|---|---|---|---|
| `intent.workflow_ref` (envelope) | `main()`, resolving the task specification | pointing it at a unit declaring a free attempt class puts `f-grunt` on the model span where the shipped declaration puts `i-fast`, and prices the plan differently, with no flag given | `test.sh` step 1b, differential |
| `observation.step_kinds` (unit) | `plan()`, and `Observation.step()` on every step | a step kind the unit did not declare is refused by name and the run stops; a unit that declares three kinds cannot be observed at four | `test.sh` step 1b, differential |
| `isolation.egress_allowlist` (unit) | `IsolationDeclaration.from_dict()`, and the `cell-admitted` record | with `egress: allowlist`, one host versus two puts a different list on the receipt, and an allowlist that lists nothing is refused `document-invalid` rather than admitted as an open unit | `test.sh` step 1c, differential plus a refusal |
| `ceilings.cancel_grace_s` (unit) | the containment adapter, at every `prompt()` — not only under `--cancel` — and the accepted window lands on the dispatch step with the floor it was accepted against | two legal graces are two runs: 0.5s and 1.25s put different cancel windows on the span, on the log record and on the receipt's attribute list, against one floor that is the host's and does not move; 0.01s is below that floor and the turn is refused with the floor named | `test.sh` step 1c, two legal values plus a refusal |
| `tools.server_ref` (unit) | `bind_server()`, which derives the binding handle from it | two references give two binding handles on the tool span, so a unit pointed at a second catalogue is a second binding and not the same one relabelled | `test.sh` step 1c, differential |
| `ceilings.wall_seconds` (unit) | `UnitContext`, and the deadline `Dispatch` holds outside the turn — and the ceiling the cell was admitted under lands on the `cell-admitted` record | 0.001s ends the unit at the boundary with exit 3; 5.0s and 9.0s both complete, and the two runs differ on the ceiling the receipt says they were admitted under, rather than being the same record twice | `test.sh` step 1c, two legal values and the threshold |
| `tools.ceiling_calls` (unit) | `CallContext`, on every call the capability makes | 0 raises a typed `budget-exhausted` at the point of call; 8 and 3 both complete, and the tool span carries the permitted count beside the attempted count, so a run that stayed inside its ceiling still records which ceiling it stayed inside | `test.sh` step 1c, two legal values and the threshold |

## 4. What the user sees

| Surface | Content | Evidence |
|---|---|---|
| The plan table, before anything runs | Every step of the unit with its model class and its estimate in micros, then the shortest finishing path and the ceiling — printed before a cell is admitted | `F-b1-06` "Cost is knowable before commitment. Planning is a pure function and completes before execution begins." |
| The trajectory | One row per typed event the declared surface renders: `run.started`, `step.progress` (one per turn frame the boundary saw), `tool.proposed`, `human.ask`, `human.decided`, `human.refused`, `run.finished`. Seven of the eight published types; `ask.expired` is the one this example does not produce, because no deadline passes here | `X-entry-composition-021` "Each event carries a type field that identifies the action taking place"; `X-litmus-b-003` "Streaming provides real-time, incremental updates for tasks" |
| The task status | One of submitted, working, input-required, completed, failed, cancelled, rejected — a pure projection over the event stream, printed for both surfaces. There is no status-change event in the published vocabulary and no capability operation that returns the status, so it is derived here rather than subscribed to (gap G2) | `X-litmus-b-003` "Tasks progress through a defined lifecycle including submitted, working, input-required, completed, and failed states." |
| The signals table | Per kind — span, metric, log record, problem object — how many were read back off the backend's own query surface, and how many were missing the run id or the correlation id. All four kinds are counted separately, never as one total | `REF-docs/maturity/closures.md#C09-F` "the audit counts each of the three"; `F-b1-08` "Telemetry, policy, provenance and budget are applied by the platform, not requested by the caller." |
| The proof line | Distinct minted trace ids, groups on the run id, levels covered, spans sampled out, problem objects whose trace names no exported span, and the cost total carried on metrics | `F-a7-02` "A depth-3 task tree produces three unrelated root traces."; `X-litmus-b-014` "you will see two disconnected traces instead of one continuous workflow" |
| Inside the unit | What the boundary can see of the turn: the negotiated session capabilities, one `step.progress` event per update frame, the stop reason, the frame count and the count of frames after the terminal one. What the unit did *between* two frames is not observable through any operation on file — gap G1, and the subject of `REF-docs/architecture/proposed/watch.json` | `REF-harness/containment/README.md`; proposed: the frame-to-event mapping is this example's own, because a frame carries a sequence number, a kind and free text and nothing else |
| The receipt: `out/*.jsonl` | One hash-chained record per thing that happened — `unit-submitted`, `step-observed`, `cell-admitted`, `refusal`, `approval-parked`, `approval-returned`, `unit-completed \| unit-cancelled \| unit-rejected` — each stamped with run id, correlation id, actor, delegation depth, entry kind and idempotency key | `F-b2-06` "append-only across runs; the deduplication authority"; `F-b4-03` "Every action names an actor, including delegated agent actors." |
| A refusal that ends the unit | `application/problem+json` on stdout and exit 2, *and* a problem-object signal on the same run resource, *and* a `run.finished` event: a failure is recorded like any other outcome, not only printed. Two of them, both measured: `document-invalid` (422) for a malformed envelope or a malformed watch declaration, and `budget-exhausted` (402) when the shortest finishing path exceeds the ceiling, refused before any cell is admitted | `F-b4-04` "Refusal is deterministic and happens before execution, not after spend"; `F-b4-07` "Typed and machine-readable. Never parsed from prose" |
| A refusal folded into the record | Refused before dispatch, recorded in a `refusal` ledger row with its deciding rule, emitted as a problem-object signal, and the unit continues to `completed`. Two of them, both measured: `policy-denied` (403) with `rule_id` `read-only-verdict`, for a tool call outside the policy verdict; and `idempotency-conflict` (409) for a second, different decision on an ask already decided, which also becomes a `human.refused` event on the stream | `F-b4-04` "Refusal is deterministic and happens before execution, not after spend"; `F-b4-08` "Every externally-triggered action is safe to replay" |
| A refusal of the observation, not of the run | A replay position asked of a surface that declares it cannot replay returns `document-invalid` (422) naming the surface, printed as problem details while the run itself reaches `completed` and exits 0. One of them, measured | `F-b4-07` "Typed and machine-readable. Never parsed from prose" |
| Per door, the lifecycle and whether the reader may subscribe or cancel | submitted → working → completed; → input-required when the caller declared a decision, and back to working on the decision; → cancelled when the reader cancels, which is negotiated at session open and enforced by the boundary through its grace window. A `stream` surface may subscribe and replay from a position; a `poll` surface may not, and says so by declaration | `X-litmus-b-003` "an explicit task lifecycle with terminal states, streaming subscription, and cancellation" |

## 6. Extension points

| Where a builder adds | Without touching | How | Proved by a differential run |
|---|---|---|---|
| A different telemetry backend | `run.py`, the entry documents, the unit declaration | write an adapter under `harness/observability/adapters/` exporting `Adapter` and set `ADAPTER`; the call shape does not change | `test.sh` step 9: the same unit on both backends returns identical per-kind counts and identical values for six counters, while the adapter name and `semantic_queries_supported` differ (`F-b1-02` "The core imports interfaces, never implementations.") |
| A different surface to watch from | `run.py` | write a surface under `harness/human-interaction/adapters/` declaring its own `delivery_model` and `replayable_from_position`, and name it in `payload.watch.surface` | `test.sh` step 6: the same run on `stream` and on `poll` renders 8 and 0 of the same 8 stored events, and the position field succeeds on one and is refused 422 on the other |
| A different level of detail | the emission path | change `payload.watch.detail`; the spans follow, and so do the trace ids | `test.sh` step 3: `steps` gives 4 operations and 4 minted traces, `unit` gives 1 and 1, from one runner |
| A different retention policy | the emitters | change `payload.watch.sampling.head_percent`; the unit's `retain_always` still outranks it | `test.sh` step 4: 100 vs 0 gives 4 spans vs 0 with an identical cost total on the metrics, a rejected run keeps its span at 0, and a caller that tries to add `retain_errors` is refused 422 |
| A different redaction set | the emitters | add keys to `payload.watch.redact_additional`, or to the unit's `redact_always`; the caller's list is unioned with the unit's, never substituted | `test.sh` step 5: the same door with and without `task_summary` puts `[redacted]` or the caller's text on the wire, while `prompt` and `completion` are `[redacted]` in both |
| A different attribute vocabulary | every emitter | revise the mapping table in `harness/observability/interface.py` and bump its version; nothing in this example writes an operation name down, and a kind the table does not carry is recorded as unmapped rather than guessed | `test.sh` step 3: the operations on the wire are a subset of the published mapping's values, the emitted mapping version is read off the wire, and `model` is reported as an unmapped kind because the table has no row for it |
| A different egress posture | `run.py`, the entry documents | set the unit's `isolation.egress` to `allowlist` and name the hosts; the declaration is resolved by the containment capability and the admitted list lands on the receipt | `test.sh` step 1c: with `egress` held at `allowlist` in both arms, one host and two put different lists on the `cell-admitted` record, and an allowlist that lists nothing is refused `document-invalid` rather than admitted as an open unit |
| A different tool catalogue | `run.py`, the entry documents | point the unit's `tools.server_ref` at another server; the capability derives the binding from the reference it was given | `test.sh` step 1c: two references give two binding handles on the tool span, so a second catalogue is a second binding and not the same one relabelled |
| A different step vocabulary inside the unit | — | **not available.** The only thing the boundary receives from inside a turn is a frame with a sequence number, a kind and free text; there is no operation to add a step through. See gap G1 | — (this row is a gap, not an extension point) |

### Carried and not consumed

| Field | Where | Why it is here anyway | Research query |
|---|---|---|---|
| `budget.currency` | the entry envelope | Every price in this example is in micros and nothing converts between currencies, so the field records the unit of account and no decision reads it | at what boundary does a budget ceiling stop being a number and become a currency — the routing table's own unit price, the ledger, or the caller's invoice |
| `budget.on_exceed` | the entry envelope | The entry schema fixes it as a `const`, which is the point ("on_exceed is a const so no caller can opt out"): there is exactly one behaviour, so reading the field could only confirm the constant. Recorded here rather than dressed up as a branch with one arm | should a guarantee a caller cannot decline be carried on the envelope at all, or is a member with one legal value a field that documents the platform rather than the request |
| `correlation.parent_correlation_id` on `entries/external.json` | the entry envelope | The runner stamps `run.id`, `correlation.id`, `correlation.depth` and `entry.kind` onto every signal, and the resource mapping has a `correlation.parent_id` key — but this run binds its own root, so the partner's upstream correlation reaches the ledger only as part of the envelope and never becomes an attribute. Nothing here would behave differently if the field were deleted | how does a correlation identifier minted by another organisation's platform join to one minted here — a second attribute, a span link, or a hop in the delegation chain |

### Gaps this example exposed

| Gap | Claim that is not supported here | Research query |
|---|---|---|
| G1 | The inside of the unit is a frame count. `step.progress` carries a frame number and the total, because a `TurnFrame` carries a sequence number, a kind and free text — so "the steps inside a unit" is, here, the outside of the unit counted. It is the subject of `REF-docs/architecture/proposed/watch.json`, whose rows are all proposed and each carry the query that would close them | what step-level record does an agent runtime protocol publish from inside a sandbox — identity, ordering, and what a client may assume when frames are lost or reordered |
| G2 | No capability operation returns the task status. `run.py` projects it from the event stream in nine lines, and the published event vocabulary has no status-change event, so a subscriber that does not know the projection rule sees no state at all | should a status read and a status-change event sit on the human-interaction interface, on dispatch, or on a read-side capability of their own |
| G3 | Head sampling breaks the three-kind trace binding. At `head_percent` 0 the problem object is retained and its trace id names a span that was never exported; `test.sh` measures exactly that (0 orphans at 100, 1 at 0) rather than describing it | how do head and tail sampling interact with a guarantee that failures are always retained — is the retained problem object re-parented, re-emitted with its span, or accepted as an orphan |
| G4 | The closed registry closes the extension members too. `budget-exhausted` declares only `stop_reason`, so which ceiling was exceeded and by how much are refused as members and survive only in `detail` prose — the one place the concern says a caller must never read. The refusal is recorded in the run report, not smoothed over | what governs adding an extension member to a closed problem-type registry, and how does a caller discover which members a type carries |
| G5 | Redaction is by attribute key, not by content. `prompt` and `completion` never reach the wire, and the same text under `task_summary` does unless a caller names that key too — measured, in both directions | what does prompt and completion scrubbing look like when the same content appears under an attribute name the redaction list does not carry |
| G6 | A failure before the envelope validates has no correlation to ride on. A malformed envelope is printed as problem details and exits 2, and writes no ledger and no telemetry, so the one failure the concern most wants correlated is the one that is not | where does a validation failure's correlation identifier come from when the document that would carry it is the thing being rejected |
| G7 | There is no callback. The human-interaction interface publishes ask, watch, decide and expire, so a caller that cannot hold a subscription open has polling and nothing else — and two of the four doors are systems with nobody at a screen | how is push delivery to a caller-owned endpoint expressed as a capability operation — registration, retry, ordering, and the failure mode when the endpoint is gone |
| G8 | The mapping description publishes operations and not instruments, so an unmapped instrument name falls through under the platform's own string with nothing recorded, while an unmapped operation is detected and reported | should a telemetry mapping description publish its instrument names alongside its operation names, and what does an emitter do with an instrument the description does not carry |
| G9 | Nothing here is a real backend. Both adapters run in process, so "switching backends is a configuration change" is measured against two in-process execution models and claimed against a collector | run the same unit against a collector and a hosted ingestion API and compare the six counters the swap proof reads |
| G10 | The area has a visible check and no hidden one. The index expects a held-out check outside `examples/`; this author's brief permits touching only `examples/watch/` and `docs/architecture/proposed/watch.json`, so the area is, by the skill's own rule, incomplete rather than passing | where does an area's held-out check live, who writes it, and what does the index report for an area with a README and no hidden check |
| G11 | No legal cancel grace changes what the boundary does. The window is accepted at every `prompt()`, recorded on the dispatch step and enforced against the running adapter's floor — but that adapter polls for cancellation every 0.02s, below its own 0.05s floor, so a unit always yields its terminal frame inside any accepted window and the boundary's `cancel_timeout` path is unreachable from a declaration. The field is therefore measured on the record and claimed on the outcome | what does a cancel grace have to be declared against for the window a caller picks to be decidable — the runtime's cancellation poll interval, its teardown cost, or a published worst case to a terminal frame the caller can read before declaring one |
