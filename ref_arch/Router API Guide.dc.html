Router API guide: how the control plane meets the agentic stack

The mobile control plane is a thin client. It owns no agent state. Everything it shows is a read model over the Ledger and the trace store; everything it does is a typed command routed through the platform's existing capability interfaces. This guide names those seams, the objects that cross them, and the vocabulary they use.

Audience · platform + front-end engineersStatus · proposal, not measuredStandards · ACP · MCP · A2A · CloudEvents · OTLP GenAI · RFC 9457 · RFC 5545
01 · Principles

Six rules the router inherits from the architecture

The UI never talks to a product

It talks to the Dispatch, State, Telemetry and Policy interfaces. LiteLLM, Temporal, Langfuse and Firecracker appear only as today's adapters.

Every command is a typed intent

Nudge, Redefine, Escalate, Extend, Restart, Reassign, Cancel, Approve, Reject, Return. No free-form prompts cross the boundary from the phone.

Cross-cutting concerns are applied, not requested

Identity, budget, policy, provenance and idempotency are stamped on every command by the router. The client cannot omit them.

The grader stays invisible

The operator sees the Judge criterion; the agent never does. Redefine edits the Document, then the Planner re-runs. The UI never pushes a criterion into a session.

Errors are RFC 9457, never prose

Each stuck reason in the UI maps to a problem type URI. The lens grid is a group-by on type.

Correlation rides on attributes

Per finding A7-1, the UI joins on cell.id and document.id resource attributes, never on trace parentage.

03 · Topology

Where the router sits

Why a router and not direct calls. Three of the seven cross-cutting concerns (identity, idempotency, policy-before-spend) are absent or unwired today (A6). The router is where they become non-optional for every client, including this one.

05 · Commands

The ten operator intents, and what each routes to

One endpoint, one envelope, ten verbs. The router validates the verb against the cell's current status, asks Policy, stamps identity and idempotency, then calls exactly one capability.

VerbValid fromCapability callSemantics
nudgestuck · waitingAgent runtime · session/promptNew turn, same intent and DoD. Cheapest action; increments nudges. Nudge count feeds the Loop.
redefineany non-doneState · write Document rev; Planner · replan; Dispatch · resume from checkpointEdits intent, DoD or steps. Creates a new Document revision; the Ledger keeps the chain.
escalatestuck · runningModel access · route to i-escalateClass change with a higher ceiling. Budget scope re-issued.
extendstuck (budget) · runningBudget · raise ceiling on the scoped virtual key+50% by default. Bulk from the Cost view.
restartstuck · waitingDispatch · terminate unit; dispatch again with same cell.idFresh microVM, resume at the last checkpointed step. Idempotency key prevents double-dispatch.
reassignany non-doneModel access · set classCaller names a class, never a vendor. Ceiling follows the class contract.
cancelany non-doneAgent runtime · session/cancel; Dispatch · terminateMeasured today: turn ends in ~8s against a 45s operation.
approveparkedDurable execution · signal gate; approve.serviceReleases the human gate. Actor identity recorded in the Ledger.
rejectparkedDurable execution · signal; Dispatch · terminateEnds the unit. Verdict recorded as operator rejection, not Judge FAIL.
returnparkedDurable execution · signal with noteCell stays parked; note becomes a Document annotation the agent reads on the next turn.

Policy runs before spend. A deny returns 403 with a problem of type urn:cellplane:problem:policy-denied and the Rego rule id. The UI shows this as a parked cell with Approve / Return, not as an error toast.

07 · Events

One stream, CloudEvents envelope, GenAI attributes

The live view is a subscription, not a poll. Every state transition is emitted once with the same cell.id attribute the trace store uses, so the timeline and the fleet map agree by construction.

08 · The loop

Findings and proposals are Ledger queries with a write-back

Observe

Every problem.raised is appended to the Ledger with type, Document, spend at failure.

Detect

A finding is any (Document, type) pair with recurrence ≥ 2 in the window.

Propose

Each type has a proposal template targeting Document, dispatch config, or schedule.

Apply

Operator-only. Writes a Document revision; provenance record names actor and prior hash.

Measure

Recurrence since the revision vs before. Revert is a further revision, never a delete.

EndpointBehaviour
GET /v1/findings?window=7dGrouped Ledger read. Includes count, costLost, nudges, proposal, applied, recurrence.before / since.
POST /v1/findings/{id}/applyCommand. Routes to State (Document revision) or dispatch config. Policy-checked. Returns the new revision id.
POST /v1/findings/{id}/dismissOperator judgement recorded in the Ledger; the finding is suppressed for the window.
POST /v1/documents/{id}/revisions/{rev}/revertNew revision equal to the prior content. The chain stays intact.

Guardrail. The loop proposes edits to what the agent is asked (intent, steps) and how it is run (ceiling, class, backoff). It never edits the Judge criterion by itself; a DoD change is an operator command with a provenance record, so the grader stays outside the graded system (B1 rule 6).

10 · Open decisions

Not decided here, and what would decide it

QuestionEvidence that would settle it
Does redefine resume from checkpoint or restart the unit?Measure whether goose honours a mid-session Document change via ACP without a fresh session. If not, redefine = revision + restart.
Where does stage live: Planner attribute or step-name heuristic?Planner output schema. The UI currently infers stage from step names; that is a placeholder.
Is the stream per-operator or fleet-wide?Event volume at 500 cells. If > 20 events/s, filter server-side by Document or group.
Saved groups: client state or Ledger object?Whether groups need to be shared across operators. If yes, they become a Document-like object with identity.
Approve via router or direct to approve.service?approve.service is Tailscale-bound today. Routing through the router adds identity and idempotency it lacks (A6).
