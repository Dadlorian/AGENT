## Rules the run area paid for (row 75 boundary, from kb/ceremonies/75-run-review.json; keep every rule above, these are additions)
- A value the README calls declared is read at the point of decision, not transcribed beside it. The run area wrote `LADDER = ("f-", "b-", "i-", "cli-")` under a comment saying the ladder was read from the routing table (R75RUN-002), hardcoded its loop bound while the unit declared `escalation.class_steps_permitted` and read that field only to copy it onto the ledger (R75RUN-005), and fanned out from `--fleet` while every envelope carried `payload.fleet_size` (R75RUN-010). If the runner would behave identically with the field deleted, the field is decorative: either read it or say in section 6 that it is carried and not consumed, with the research query.
- Prove every extension point by a differential run, in test.sh: the same door or unit twice, one declared value changed, the two records asserted different in the named way (class_steps_permitted 0 gives no `escalated` record, 1 gives exactly one; the schedule door bare gives the width its envelope declares, `--fleet 4` overrides to four). An extension-points row with no such check is a claim; mark it proposed with its reasoning, or make it a gap. A green run at the default value proves the default path and nothing else.
- Never write a count you have not read back out of the artifact. The run area claimed "one hundred distinct cells" where out/fleet.jsonl holds 100 attempt cells and 100 measure cells (R75RUN-004), and the wrong gloss was already copied into the README, provenance.json and test.sh's check label. Compute the number in the check and let the label carry the same number.
- Name only the failure modes your code produces. The run area's refusal row listed `policy-denied` 403 and `isolation-unavailable` 503, which no path reaches (R75RUN-006); refusals that end the unit and refusals folded into a record and never surfaced are two different rows and are measured differently.
- Gate test.sh on its own count as well as on its failures, as instruction 6 of build-example says: `FLOOR=<n>` at the top and `[ "$PASS" -ge "$FLOOR" ] || { echo "the visible check counted $PASS, below the floor of $FLOOR"; exit 1; }` beside `[ "$FAIL" -eq 0 ] || exit 1`. Without the floor a gutted copy prints `passed 0, failed 0` and exits 0 (R75RUN-007). Keep provenance.visible_checks_counted in step with the floor.
- provenance.cites is exactly the record ids the example's rows carry - grep them out of README.md, the .py files, test.sh, units/ and contract/ - not a reading list. The run area's list was neither a superset nor a subset: it missed the one research id the README quotes and carried 24 ids appearing nowhere (R75RUN-008), so it could not be checked in either direction. A claim the run does not measure goes under claimed, never under measured (R75RUN-012: a cell admitted, ledgered and terminated while the checks run host-side is anti-tamper claimed, not proved).
- Every cell of a table says its own thing: "as above" carried one adapter's execution model onto two adapters that work nothing like it (R75RUN-009), and a column header must be true of every cell under it.
