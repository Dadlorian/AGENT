## Rules the run area paid for (row 75 boundary, from kb/ceremonies/75-run-review.json; keep every rule above, these are additions)
- A value the README calls declared is read at the point of decision, not transcribed beside it. The run area wrote `LADDER = ("f-", "b-", "i-", "cli-")` under a comment saying the ladder was read from the routing table (R75RUN-002), hardcoded its loop bound while the unit declared `escalation.class_steps_permitted` and read that field only to copy it onto the ledger (R75RUN-005), and fanned out from `--fleet` while every envelope carried `payload.fleet_size` (R75RUN-010). If the runner would behave identically with the field deleted, the field is decorative: either read it or say in section 6 that it is carried and not consumed, with the research query.
- Prove every extension point by a differential run, in test.sh: the same door or unit twice, one declared value changed, the two records asserted different in the named way (class_steps_permitted 0 gives no `escalated` record, 1 gives exactly one; the schedule door bare gives the width its envelope declares, `--fleet 4` overrides to four). An extension-points row with no such check is a claim; mark it proposed with its reasoning, or make it a gap. A green run at the default value proves the default path and nothing else.
- Never write a count you have not read back out of the artifact. The run area claimed "one hundred distinct cells" where out/fleet.jsonl holds 100 attempt cells and 100 measure cells (R75RUN-004), and the wrong gloss was already copied into the README, provenance.json and test.sh's check label. Compute the number in the check and let the label carry the same number.
- Name only the failure modes your code produces. The run area's refusal row listed `policy-denied` 403 and `isolation-unavailable` 503, which no path reaches (R75RUN-006); refusals that end the unit and refusals folded into a record and never surfaced are two different rows and are measured differently.
- Gate test.sh on its own count as well as on its failures, as instruction 6 of build-example says: `FLOOR=<n>` at the top and `[ "$PASS" -ge "$FLOOR" ] || { echo "the visible check counted $PASS, below the floor of $FLOOR"; exit 1; }` beside `[ "$FAIL" -eq 0 ] || exit 1`. Without the floor a gutted copy prints `passed 0, failed 0` and exits 0 (R75RUN-007). Keep provenance.visible_checks_counted in step with the floor.
- provenance.cites is exactly the record ids the example's rows carry - grep them out of README.md, the .py files, test.sh, units/ and contract/ - not a reading list. The run area's list was neither a superset nor a subset: it missed the one research id the README quotes and carried 24 ids appearing nowhere (R75RUN-008), so it could not be checked in either direction. A claim the run does not measure goes under claimed, never under measured (R75RUN-012: a cell admitted, ledgered and terminated while the checks run host-side is anti-tamper claimed, not proved).
- Every cell of a table says its own thing: "as above" carried one adapter's execution model onto two adapters that work nothing like it (R75RUN-009), and a column header must be true of every cell under it.

## Rules the ask, watch and steer areas paid for (row 75 boundary, from kb/ceremonies/75-{ask,watch,steer}-review.json; every rule above still holds)
- A sentence that names its own proof is a promise to falsify. Before writing "proved by `test.sh` section N", break the claim and check that section N goes red; if the suite stays green the sentence is decoration. watch's only check for the claim its README leads with, "one declaration, four doors", was `assert len({tuple(sorted(...))}) == 1` - a set holding one tuple, length 1 whatever the four documents say (R75WATCH-003); `pause_for_decision` was "Proved by `test.sh` steps 2 and 7", where step 2 reads only the door that declares it true and step 7 reads one declaration once (R75WATCH-005); ask's "scope narrows along the chain" check compared the human door (1 hop) with the external door (3 hops), two different chains rather than two hops of one (R75ASK-004); steer's section 7 proved fail-closed at the five points already registered, not the two things its extension row claimed (R75STEER-007).
- Assert on what the artifact holds, never on the literal your own code just set. steer asserted "2 to 1" off `report["decisions_at_effect"]`, a constant the branch had written, where the number is `len([r for r in rep["decisions"] if r["decision_point"] == "dispatch.tool_call"])` counted out of the rows (R75STEER-008); and a headline saying the decision is "byte-identical" at four sites was backed by a check comparing five members while four `input_digest` values differ, so the sentence had to become "identical in point, action, effect, rule and resource" with the reason it is not byte-identical (R75STEER-009). Write the sentence the check can support, or make the check support the sentence.
- A scan check's scope equals the scope of the sentence it backs, and says so in its own message. The no-product-name check greps every source file and every artifact the run has written by that point, word-anchored, and prints how many it scanned. All four areas shipped it narrower than its claim: 10 files with unanchored substrings and 17 names, so the three-letter engine name needed a trailing space to dodge "opaque" and cedar, firecracker, gvisor, jaeger and datadog were absent (R75ASK-008); one `out/human.log` out of roughly forty and seventeen artifacts (R75STEER-010, R75WATCH-009). The same rule applies to a cites walk: watch's skipped `docs/architecture/proposed/watch.json`, the area's second deliverable, which its own provenance cites (R75WATCH-010).
- Quote by lookup, never from memory. Every quoted string in the README, in a unit's `_` note and in provenance.json is pasted out of the record it names, and one grep back into that record must return it. This is the cheapest check in the area and it caught the block finding in four areas of four; the misquotes were single words (`token` for `actor_token`, `tracked` for `recorded`, "creating our own framework" for "modelling our own shape") in rows whose ids the same file quoted correctly a dozen lines later.
- A note that counts something ("README section 6 names the one field...", "sixteen record kinds", "every one of them is named") is a count read back out of the thing it describes, in both directions. watch's unit note said one carried-and-not-consumed field where the table has three (R75WATCH-006); steer's provenance claimed sixteen record kinds where the ledger the check reads carries thirteen (R75STEER-006); ask's dropped-list row was true one way only, naming members the run drops and missing `datacontenttype` and `priority` (R75ASK-007).
- Key a list a reader is sent to by id, not by position: watch's assertion messages pointed at "gap 1" and "gap 6" after the gap table had been renumbered, so the table is now keyed G1..G10 and every reference resolves into it (R75WATCH-007). And keep one emission path one path - `park_and_resume` appended two event names straight onto `obs.events`, bypassing the vocabulary gate the README sells as the single door (R75WATCH-008).
