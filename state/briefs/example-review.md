## What the run review found, and the check that catches it faster (row 75 boundary; everything above still holds)
- Add `inert-declaration` to the kinds list and look for it first. Five of the twelve run findings were one defect: a value the README sells as declared, read from somewhere else at the point of decision - a literal tuple beside a comment claiming it was read from the routing table (R75RUN-002), a hardcoded loop bound beside a declared `class_steps_permitted` that was only copied onto the ledger (R75RUN-005), `--fleet` doing the fan-out the envelope declared (R75RUN-010), refusal types named in prose that no path produces (R75RUN-006), a measure cell admitted and terminated while the checks ran host-side (R75RUN-012). Every one passed the area's own `passed 46, failed 0`, because the visible check ran only the default value.
- The mechanical form: grep the field names out of `examples/<area>/entries/*.json` and `units/*.json` and the knob names out of the extension-points table, then for each ask whether anything reads it at the point of decision and whether any check varies it. A name that is neither varied by a check nor written up as a carried-and-not-consumed gap is a finding. Delete the field, or set it to a second value, and re-run: if the records are identical the row is decoration. `docs/night/hidden/run.sh` h-08 is exactly this for one field - it ran the unit at `class_steps_permitted: 0` and still got an `escalated` record and a moved class; write one such differential assertion per declared value, not one per area.
- Read every count back out of the artifact rather than out of the prose: the run area's "one hundred distinct cells" was 200 in out/fleet.jsonl (R75RUN-004), and the same wrong gloss sat in the README, provenance.json and test.sh's check label, so agreement between three files is not evidence.
- Check the gate itself: `[ "$FAIL" -eq 0 ] || exit 1` with no floor passes a gutted copy that counts nothing (R75RUN-007). Assert a floor from outside too (h-12 asserts N >= 20).
- Check provenance.cites in both directions - every id the rows carry is in it, and every id in it appears in the example (R75RUN-008) - and that anything the run does not measure sits under claimed.
- On plants: both run plants were single-site insertions, one a quote appearing nowhere in the repository while the same id was quoted correctly twelve lines later, one an added table row duplicating a cited row with every term renamed and a circular reason. Rank candidates by that shape, and separate them from authorial habits, which repeat across sites (a count wrong in three files) or have siblings (an unread declared field beside `template`, `form`, `source_ref`).
