## What the run review found, and the check that catches it faster (row 75 boundary; everything above still holds)
- Add `inert-declaration` to the kinds list and look for it first. - The mechanical form: grep the field names out of `examples/<area>/entries/*.json` and `units/*.json` and the knob names out of the extension-points table, then for each ask whether anything reads it at the point of decision and whether any check varies it. A name that is neither varied by a check nor written up as a carried-and-not-consumed gap is a finding. Delete the field, or set it to a second value, and re-run: if the records are identical the row is decoration. `docs/night/hidden/run.sh` h-08 is exactly this for one field - it ran the unit at `class_steps_permitted: 0` and still got an `escalated` record and a moved class; write one such differential assertion per declared value, not one per area.

- Check provenance.cites in both directions - every id the rows carry is in it, and every id in it appears in the example (R75RUN-008) - and that anything the run does not measure sits under claimed.
- On plants: both run plants were single-site insertions, one a quote appearing nowhere in the repository while the same id was quoted correctly twelve lines later, one an added table row duplicating a cited row with every term renamed and a circular reason. ## What the ask, watch and steer reviews found, and the check that catches it faster (row 75 boundary; everything above still holds)
- Add `proof-not-of-the-claim` to the kinds list, beside `inert-declaration`. The recurrence across all three areas is a check believed on its label: watch's only check for "one declaration, four doors" was `assert len({tuple(sorted(...))}) == 1`, a set of one tuple that cannot fail (R75WATCH-003); "Proved by `test.sh` steps 2 and 7" where neither step runs the differential (R75WATCH-005); ask's chain-narrowing label comparing a 1-hop door with a 3-hop door instead of two hops of one chain (R75ASK-004); steer's section 7 proving fail-closed rather than the two things its row claimed (R75STEER-007); an assertion on a literal the runner had set rather than on the rows (R75STEER-008); a "byte-identical" sentence over a check comparing five members while four digests differ (R75STEER-009). Each was green in an area printing `failed 0`.
- The mechanical form: take every sentence that names its own evidence - a record id with a quote, a `test.sh` section or step, a printed command with its promised last line, a scan - and falsify it rather than read it. (a) grep the quote verbatim out of the cited record; any byte difference is a block. (b) Break the claim in a scratch copy and require the named section, not the suite, to go red; a section that stays green proves something else. (c) Run the printed command exactly as printed and diff both its exit and its last line against the row, and check every flag against the runner's argparse. (d) Read the scan's own scope against the scope of the sentence it backs.
- Run (a) first, over the whole area, before reading anything else. It is one pass, needs no judgment, and caught the block finding in four areas of four; all four block misquotes were single words in an Ideal-table row whose id the same file quoted correctly a dozen to ninety-three lines later.
- Scan checks are narrower than their claims by default: 10 files, unanchored substrings and 17 names (R75ASK-008); one `out/human.log` out of roughly forty artifacts (R75STEER-010) and out of seventeen (R75WATCH-009); a cites walk that skipped the area's second deliverable `docs/architecture/proposed/<area>.json` while provenance cited it (R75WATCH-010). Ask of every scan: how many files, matched how, against a claim about what.
- Counts drift in one direction: check both. A unit note claiming README section 6 names one carried field where the table has three (R75WATCH-006); "sixteen record kinds" against a ledger carrying thirteen (R75STEER-006); a dropped-list row true one way only (R75ASK-007). Also check that a reference into a numbered list still resolves after renumbering (R75WATCH-007), and that a path the README sells as the single emission door is not bypassed elsewhere in the runner (R75WATCH-008).
- Also look for an unguarded call to a store operation that refuses: steer's `expire` was called whenever `decision` was "none", and any schema-valid declaration with a delay inside the deadline made it raise where every neighbouring call was wrapped (R75STEER-002). A path that no shipped declaration reaches is still a path a reader's declaration reaches.
- On plants, the shape held in all four areas: a single-site misquote in the Ideal table, and a single-site table row duplicating its neighbour with a promise the program does not keep (a `--show-response` flag argparse does not define; a thirteenth run step repeating step 2's command with a last line the program never prints; a "unified framework" row renaming every term of the cited row above it). Nominate on that shape and say why, as all four reviews did.
